# Making c2pa-rs sign post-quantum

These reproduce the result in Section 8. They are against `c2pa-rs` at
commit `d589cf7` (24 September 2026) and `c2pa_raw_crypto` 0.1.2 from
crates.io, built with `rustc` 1.98.1.

Nothing here touches `coset`. The COSE library already carries the RFC 9964
identifiers — `ML_DSA_44`, `ML_DSA_65` and `ML_DSA_87` at -48, -49 and -50 —
and needed no change.

## What each file does

`c2pa_raw_crypto-signing_alg.patch`
: Adds three variants to `SigningAlg`, with their `FromStr` and `Display`
  spellings. Applying this alone breaks exactly two matches in that crate:
  the signer factory and the validator factory.

`mldsa_signer.rs`, `mldsa_validator.rs`
: Fill those two matches, against RustCrypto's `ml-dsa` 0.1.1. Drop them into
  `src/rust_native/signers/` and `src/rust_native/validators/` and register
  them in the respective `mod.rs`.

`c2pa-rs-rfc9964.patch`
: 35 lines across four files in the SDK. The COSE algorithm mapping when
  signing (`cose/sign.rs`), the reverse mapping when verifying
  (`cose/sign1.rs`, both the assigned and private-use branches), the
  verifier's check of the signing algorithm against the subject key's OID
  (`cose/verifier.rs`), and the certificate profile's own allow-list of
  permitted certificate signature algorithms (`cose/certificate_profile.rs`).

## Why it took four changes rather than one

Three of those four are allow-lists that must agree, and each ends in a
catch-all that rejects rather than in an exhaustive match that fails to
compile. Adding the enum variants therefore produces no compiler error at all,
and the library still refuses to sign, reporting one unsupported-algorithm
error that names none of the gates.

## Building

```bash
git clone https://github.com/contentauth/c2pa-rs
cd c2pa-rs && git checkout d589cf7
git apply /path/to/c2pa-rs-rfc9964.patch
# patch c2pa_raw_crypto from the registry copy, then:
printf '\n[patch.crates-io]\nc2pa_raw_crypto = { path = "/path/to/patched" }\n' >> Cargo.toml
cargo build -p c2pa --no-default-features --features rust_native_crypto,file_io
```

## One thing the patch found in our own work

Certificates generated by `src/pq_cose.py` originally carried no Subject or
Authority Key Identifier. The C2PA certificate profile requires both, and the
library rejected them with a bare "the certificate is invalid" that named
neither extension. `pq_cose.py` now adds both, which costs about sixty bytes
per certificate. Every size reported in the paper is measured with them
present.
